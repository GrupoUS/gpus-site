# Phase 3 — UI Design Contract: Visual Uplift & Animation System

> Visual and interaction contract for transforming the Grupo US site from "flat navy" to "premium immersive". Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (custom Tailwind v4 `@theme` + `@utility` in `global.css`) |
| Preset | not applicable |
| Component library | Aceternity UI (selective effects only: aurora, spotlight, beams, lamp, text-generate-effect) |
| Icon library | Lucide React (SVG only, never emojis) |
| Heading font | Playfair Display (`font-serif`) via Astro 6 Fonts API |
| Body font | Inter (`font-sans`) via Astro 6 Fonts API |

**Note:** `components.json` exists for Aceternity UI registry imports but the design system is entirely custom. No shadcn UI component primitives (Button, Dialog, etc.) are used. All visual tokens live in `src/styles/global.css` under `@theme {}`.

## Spacing Scale

Declared values (multiples of 4, matching existing Tailwind defaults):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding, icon-to-text spacing |
| sm | 8px | Compact element spacing, gap between stacked badges |
| md | 16px | Default element spacing, card internal padding base |
| lg | 24px | Section padding on mobile, card content padding |
| xl | 32px | Section vertical padding on mobile, grid gaps |
| 2xl | 48px | Desktop section padding, CTA block internal spacing |
| 3xl | 64px | Page-level section breaks (`py-16` / `py-24` on desktop) |

Exceptions:
- Touch targets for mobile menu items: minimum 44px height (existing `py-3` on `text-lg` already meets this)
- Header height: 60px fixed (existing `h-[60px]` spacer)
- Hero sections: `min-h-screen` (home) or `min-h-[70vh]` (landing) -- not governed by spacing scale

## Typography

| Role | Size | Weight | Line Height | Font Family | Usage |
|------|------|--------|-------------|-------------|-------|
| Body | 16px (`text-base`) | 400 (regular) | 1.625 (`leading-relaxed`) | Inter (`font-sans`) | Paragraphs, descriptions, subheadlines |
| Label | 14px (`text-sm`) | 400 (regular) | 1.5 | Inter (`font-sans`) | Badges, stat labels, nav links, `text-text-muted` captions |
| Heading | 30px (`text-3xl`) / 36px (`text-4xl`) | 700 (bold) | 1.2 (`leading-tight`) | Playfair Display (`font-serif`) | Section headings (`h2`), CTA headings |
| Display | 48px (`text-5xl`) / 60px (`text-6xl`) | 700 (bold) | 1.1 (`leading-tight`) | Playfair Display (`font-serif`) | Hero `h1`, stat numbers (`text-4xl` / `text-5xl` on desktop) |

Weight constraint: Two weights govern the design contract -- 400 (regular) for all body and label text in Inter, and 700 (bold) for all headings and display text in Playfair Display.

**Exception -- weight 600 (semibold):** The existing codebase uses `font-semibold` (600) across 19 files (40 occurrences) for interactive UI elements: buttons (`Button.astro`), nav CTA labels (`Header.astro`), footer section headings (`Footer.astro`), hero badges, and card subheadings in components like `PainPoints`, `Values`, `Culture`, and `TeamGrid`. Semibold provides optical distinction between interactive/emphasised labels (600, Inter) and heading text (700, Playfair Display) without the heaviness that bold Inter would impose on small-sized elements. Replacing 600 with 700 across these elements would over-emphasise UI chrome relative to actual content headings. This weight is inherited from the existing design and is not introduced by Phase 3. New Phase 3 components must use only 400 or 700; the 600 usage is frozen at its current footprint and must not expand.

## Animation Contract

This section replaces a traditional "interaction states" table because Phase 3 is entirely about animation and visual refinement.

### New CSS Utilities (added to `global.css`)

| Utility | Purpose | Scope | Reduced Motion Fallback |
|---------|---------|-------|------------------------|
| `landing-mesh-bg` | Animated mesh gradient background via `@keyframes mesh-drift` | Landing hero sections (LandingHero.astro) | Static gradient, no animation |
| `glass-card-bright` | Higher-intensity glass-card for conversion moments | Home CTASection + LandingCTA only | Same visual, no change needed (static utility) |
| `[data-glow-card]` glow effect | Mousemove-following gold radial gradient on cards | ProductsGrid cards only (home page) | Disabled entirely on touch devices (`pointer: coarse`) |

### New CSS Keyframes

| Keyframe | Duration | Easing | Iteration | Mobile Disable |
|----------|----------|--------|-----------|----------------|
| `mesh-drift` | 20s | `ease-in-out` | infinite | Yes -- disable at `max-width: 768px` (matches existing pattern) |

### Framer Motion Spring Reveals (4 sections only)

| Section | Component | Directive | Spring Config | Stagger |
|---------|-----------|-----------|---------------|---------|
| Home Hero entrance | `HeroEntrance.tsx` | `client:idle` | stiffness: 200, damping: 25, mass: 1 | 80ms between badge, headline, subtitle, CTA |
| Home CTA Section | `MotionReveal.tsx` wrapper | `client:visible` | stiffness: 180, damping: 22, mass: 1 | 0ms (single block) |
| Landing Hero entrance | `LandingHeroEntrance.tsx` | `client:visible` | stiffness: 200, damping: 25, mass: 1 | 80ms between badge, tagline, headline, subheadline |
| StatsSection | `AnimatedStats.tsx` | `client:visible` | stiffness: 200, damping: 25, mass: 1 | 60ms per stat item |

**Critical rule:** For these 4 sections, REMOVE `data-reveal` attributes from elements controlled by Motion. Motion handles opacity/transform entirely. All other sections keep `data-reveal` CSS animations untouched (D-08, D-09).

### Count-Up Animation (StatsSection)

| Stat | Target | Prefix | Suffix | Thousands Sep | Duration | Easing |
|------|--------|--------|--------|---------------|----------|--------|
| "+5.000" | 5000 | "+" | "" | "." (Brazilian) | 2s | easeOut |
| "26" | 26 | "" | "" | none | 2s | easeOut |
| "10+" | 10 | "" | "+" | none | 2s | easeOut |
| "7" | 7 | "" | "" | none | 1.5s | easeOut |

Implementation: `useMotionValue` + `animate` + `useTransform(Math.round)` from `"motion/react"`. When `useReducedMotion()` returns `true`, set final value immediately without animation.

### Button Hover Glow (all 4 variants)

| Variant | Current Hover | Added Glow |
|---------|---------------|------------|
| `primary` | `hover:bg-gold-light gold-glow hover:scale-[1.02]` | Already has `gold-glow`. No change. |
| `outline` | `hover:bg-gold hover:text-navy hover:shadow-lg hover:shadow-gold/20` | Add `box-shadow: 0 0 20px color-mix(in srgb, var(--color-gold) 25%, transparent)` on hover |
| `ghost` | `hover:bg-navy-lighter/50` | Add `box-shadow: 0 0 15px color-mix(in srgb, var(--color-gold) 15%, transparent)` on hover |
| `whatsapp` | `hover:bg-whatsapp-hover hover:shadow-lg hover:shadow-whatsapp/20` | Add `box-shadow: 0 0 20px color-mix(in srgb, var(--color-whatsapp) 25%, transparent)` on hover |

### Mobile Menu Transition (D-14)

| Property | Hidden State | Open State | Transition |
|----------|-------------|------------|------------|
| `transform` | `translateY(-100%)` | `translateY(0)` | 300ms ease-out |
| `opacity` | 0 | 1 | 300ms ease-out |
| `pointer-events` | none | auto | instant |
| `visibility` | hidden | visible | instant on open, 300ms delay on close |

Replace current `hidden`/`flex` toggle with CSS transition states. Remove `hidden` class manipulation from JS; use a `.menu-open` class toggle instead.

### Aurora Color Replacement (D-01)

| CSS Variable | Before (Aceternity default) | After (Navy/Gold brand) |
|-------------|----------------------------|------------------------|
| `--aurora` gradient | `#3b82f6, #a5b4fc, #93c5fd, #ddd6fe, #60a5fa` | `var(--color-gold), var(--color-gold-light), var(--color-navy-lighter), var(--color-gold-dark), var(--color-gold)` |
| Wrapper `className` | `bg-zinc-50 text-slate-950 dark:bg-zinc-900` | `bg-navy` |
| Inner `dark:` classes | Conditional light/dark | Remove `dark:` prefixes; site is always dark |

## Accessibility Contract

| Requirement | Implementation | Source |
|-------------|---------------|--------|
| `prefers-reduced-motion` CSS | All new CSS animations disable at `animation-duration: 0.01ms` (existing global rule) | `global.css` line 98-111 |
| `prefers-reduced-motion` Motion | Every new React island calls `useReducedMotion()` and renders static content when `true` (D-16) | CONTEXT.md |
| Mesh gradient mobile disable | `@media (max-width: 768px)` stops `mesh-drift` animation (matches `gold-pulse-glow` pattern) | RESEARCH.md Pitfall 4 |
| Touch device glow disable | `window.matchMedia('(pointer: coarse)')` skips mousemove glow registration | RESEARCH.md Pattern 4 |
| Contrast preservation | `glass-card-bright` must maintain >= 4.5:1 contrast for text over its background | `.claude/rules/a11y.md` |
| `noscript` fallback | `data-reveal` elements visible via existing `<noscript>` styles; Motion islands render static content server-side | `Layout.astro` |
| Existing Motion islands | Do NOT add `useReducedMotion` to existing Aceternity islands (lamp, text-generate-effect, beams) in Phase 3 scope. Flag for Phase 6 QA. | RESEARCH.md Open Question 1 |
